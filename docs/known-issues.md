## WindWalk: duplicate setBackstabDamage

**ID:** `objediting-windwalk-duplicate-setbackstabdamage`  
**Файл:** [`src/vendor/assets/objediting/object/AbilityObjEditing.lua`](../src/vendor/assets/objediting/object/AbilityObjEditing.lua)  
**Класс:** `AbilityDefinitionWindWalk` (parent `ANwk`)  
**Строки:** ~3395–3405

### Суть

Два метода с одним именем `setBackstabDamage`:

1. **Первый** — `value: float`, пишет в `Owk3` через `setLvlDataUnreal`.
2. **Второй** — `value: boolean`, пишет в `Owk4` через `setLvlDataBoolean`.

В Lua второе определение **перезаписывает** первое. Вызов `setBackstabDamage(level, floatValue)` в runtime попадёт в boolean-версию → неверная запись в object data.

### Почему не исправлено

- Файл autogenerated/community stub (~16k строк); правка вручную оторвётся от upstream.
- Для LuaLS добавлен `---@diagnostic disable: duplicate-set-field` на файл ([ADR 0001](adr/0001-luals-zero-warnings-trade-offs.md)).

### Варианты исправления

1. **Генератор objediting** — разные имена методов (например `setBackstabDamage` / `setBackstabDamageFlag`) или overload по разным полям в одном методе с union-типом на уровне stub только для LuaLS.
2. **Патч upstream** community type assets, если источник доступен.
3. **Локальный wrapper** в `src/lib/objediting/`, если WindWalk используется в карте — не трогать giant stub.

### Проверка актуальности

```powershell
Select-String -Path "src/vendor/assets/objediting/object/AbilityObjEditing.lua" -Pattern "function AbilityDefinitionWindWalk:setBackstabDamage"
```

Ожидается 2 совпадения — баг ещё жив.
